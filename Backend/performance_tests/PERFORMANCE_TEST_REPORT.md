# 性能测试报告

## 1. 测试概述

### 1.1 测试目的
评估麻将社区平台在正常负载和压力负载下的性能表现，识别性能瓶颈和系统极限。

### 1.2 测试环境
- **测试工具**: Locust 2.28.0
- **目标服务器**: https://120.53.120.90

### 1.3 测试范围
覆盖以下主要API端点：
- 认证API（登录、用户资料）
- 新闻API（文章列表、详情、首页）
- M-League API（排名、赛程、选手统计、积分）
- 论坛API（帖子列表、详情、最新、热门）
- 麻将API（点数计算、图片生成）
- 健康检查

## 2. 测试方法

### 2.1 负载测试（Load Test）

**测试参数**：
- 并发用户数：100
- 用户增长速率：5用户/秒
- 测试持续时间：5分钟
- 总请求数：4,651

**测试目标**：验证系统在正常负载下的性能表现，评估响应时间和成功率。

### 2.2 压力测试（Stress Test）

**测试参数**：
- 并发用户数：500
- 用户增长速率：10用户/秒
- 测试持续时间：5分钟
- 总请求数：5,256

**测试目标**：找出系统性能瓶颈和极限，评估系统在高负载下的稳定性。

## 4. 结果分析

### 4.1 负载测试分析

#### 4.1.1 性能表现良好的API
以下API在100并发用户下表现良好：
- **news_api/articles/detail**: 平均81.54ms，P95 230ms，无失败
- **health/check**: 平均72.30ms，P95 450ms，无失败
- **forum/posts/hot**: 平均86.01ms，P95 380ms，无失败
- **news_api/articles**: 平均206.29ms，P95 850ms，无失败
- **m-league/rankings**: 平均247.39ms，P95 1,900ms，无失败
- **mahjong/points**: 平均182.82ms，P95 1,500ms，无失败

#### 4.1.2 存在性能问题的API

**严重问题**：
1. **m-league/schedule（赛程查询）**
   - 平均响应时间：20,787ms（20.8秒）
   - P95响应时间：62,000ms（62秒）
   - 失败率：2.58%
   - 最大响应时间：191,286ms（3.2分钟）
   - **问题分析**：数据库查询性能极差，可能存在慢查询或缺少索引

2. **mahjong/images（麻将牌图片生成）**
   - 平均响应时间：4,610ms（4.6秒）
   - P95响应时间：14,000ms（14秒）
   - 最大响应时间：88,976ms（89秒）
   - **问题分析**：图片生成未缓存，每次请求都重新生成，导致响应时间过长

3. **auth/profile（用户资料）**
   - 平均响应时间：5,799ms（5.8秒）
   - P95响应时间：15,000ms（15秒）
   - 最大响应时间：93,302ms（93秒）
   - **问题分析**：可能存在N+1查询问题或复杂的数据关联查询

**中等问题**：
4. **forum/posts/detail（帖子详情）**
   - 平均响应时间：8,019ms（8秒）
   - P95响应时间：43,000ms（43秒）
   - 失败率：1.27%
   - **问题分析**：可能涉及复杂的关联查询或大量数据加载

5. **auth/login（登录）**
   - 平均响应时间：3,131ms（3.1秒）
   - P95响应时间：5,000ms（5秒）
   - **问题分析**：登录验证逻辑可能涉及多次数据库查询

6. **m-league/player-stats（选手统计）**
   - 平均响应时间：1,517ms（1.5秒）
   - P95响应时间：4,400ms（4.4秒）
   - **问题分析**：统计查询可能涉及聚合计算，需要优化

### 4.2 压力测试分析

#### 4.2.1 系统极限
在500并发用户下，系统出现明显的性能退化：
- 总体失败率从0.13%上升到8.30%
- 平均响应时间从2,255ms增加到12,281ms
- 大量API的P95响应时间达到60秒（超时阈值）

#### 4.2.2 严重性能问题

**最严重**：
1. **auth/login（登录）**
   - 失败率：34.40%（86/250）
   - 平均响应时间：42,770ms（42.8秒）
   - P95响应时间：61,000ms（61秒）
   - **问题分析**：登录API成为系统瓶颈，高并发下大量请求超时（HTTP 504）

2. **m-league/schedule（赛程查询）**
   - 失败率：24.68%（19/77）
   - 平均响应时间：39,272ms（39.3秒）
   - P95响应时间：101,000ms（101秒）
   - **问题分析**：数据库查询性能问题在高负载下更加严重

3. **m-league/player-stats（选手统计）**
   - 失败率：6.86%
   - 平均响应时间：22,118ms（22.1秒）
   - P95响应时间：86,000ms（86秒）
   - **问题分析**：统计查询在高并发下性能急剧下降

**高失败率API**：
4. **mahjong/points（点数计算）**
   - 失败率：12.13%（210/1,731）
   - 平均响应时间：14,724ms（14.7秒）
   - **问题分析**：计算密集型API在高并发下出现超时

5. **forum/posts/latest（最新帖子）**
   - 失败率：8.47%（10/118）
   - 平均响应时间：7,913ms（7.9秒）
   - **问题分析**：查询可能涉及排序和分页，需要优化

#### 4.2.3 错误类型分析
- **HTTP 504（网关超时）**：主要错误类型，占失败请求的绝大部分
- **HTTP 0（连接失败）**：少量请求出现连接失败

## 5. 性能瓶颈识别

### 5.1 数据库性能瓶颈
- **m-league/schedule**: 数据库查询极慢，需要添加索引或优化查询
- **m-league/player-stats**: 统计查询在高并发下性能急剧下降
- **forum/posts/detail**: 可能存在N+1查询问题

### 5.2 计算性能瓶颈
- **mahjong/images**: 图片生成未缓存，重复计算导致性能问题
- **mahjong/points**: 计算密集型API在高并发下出现超时

### 5.3 认证性能瓶颈
- **auth/login**: 登录验证逻辑在高并发下成为系统瓶颈
- **auth/profile**: 用户资料查询性能较差

### 5.4 系统资源瓶颈
- 在500并发用户下，系统资源（CPU、内存、数据库连接）可能达到上限
- 大量HTTP 504错误表明请求处理超时，系统无法及时响应

## 6. 测试结论

### 6.1 系统性能评估
- **正常负载（100用户）**：系统基本稳定，失败率0.13%，但部分API响应时间较长
- **压力负载（500用户）**：系统性能急剧下降，失败率8.30%，多个API出现超时

### 6.2 关键发现
1. **m-league/schedule**和**mahjong/images**是性能最差的API，需要优先优化
2. **auth/login**在高并发下成为系统瓶颈，失败率高达34.40%
3. 数据库查询性能是主要瓶颈，需要优化查询和添加索引
4. 缺少缓存机制导致重复计算和查询
